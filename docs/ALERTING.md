# Alerting Guide

This document defines production alert rules for backend uptime, HTTP 5xx error spikes, and database disconnects.

## Metrics Source

The backend exports Prometheus metrics at `/metrics`.

Key custom metrics:
- `vruttaant_http_requests_total`
- `vruttaant_http_request_duration_seconds`
- `vruttaant_http_errors_total`
- `vruttaant_database_connected`

The `up` metric is generated by Prometheus itself for each scrape target.

## Alert Rules

Prometheus rule file: `docs/alerts/vruttaant-alert-rules.yml`

Rules included:
- `VruttaantBackendDown`: target not scrapeable for 2 minutes
- `VruttaantHigh5xxRate`: 5xx responses exceed 5% over 5 minutes with minimum request volume
- `VruttaantDatabaseDisconnected`: backend reports DB disconnected for 2 minutes

## Prometheus Setup

Example `prometheus.yml` scrape config:

```yaml
scrape_configs:
  - job_name: vruttaant-backend
    metrics_path: /metrics
    static_configs:
      - targets:
          - localhost:5000
```

## Alertmanager Routing

Route alerts by `severity` label:
- `critical`: pager/on-call
- `warning`: Slack/email

## Operational Notes

- Tune thresholds based on real traffic after observing baseline values.
- Keep `VruttaantHigh5xxRate` volume guard (`> 20 requests/5m`) to avoid noise at low traffic.
- Use the `requestId` value in API error payloads and logs for incident tracing.
